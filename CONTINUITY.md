- 2026-08-25 [CODE] VERDICT: diagnosis directionally correct. The app's status-bar strategy (commit 7e14623 "Hide status bar in installed PWA") = manifest display:fullscreen + apple-mobile-web-app-status-bar-style=black-translucent + viewport-fit=cover — an explicit "hide the status bar" (iPhone) model, still at HEAD in BOTH repos (CONTEXT.md:54-55,101). On iPadOS the status bar is NOT hidden: WebKit bugs 264220/280181/317153 ("Home Screen web apps does not support drawing arbitrary content below the status bar"); display:fullscreen is ignored.
- 2026-08-25 [CODE] No iPad-specific safe-area zeroing exists: the only query that zeroes/caps safe areas is @media (max-height:500px) and (orientation:landscape) (css/unified.css:806 / 883-889) — cannot match iPad landscape (H≥768). --safe-* = min(env(...),cap) are honored verbatim on iPad.
- 2026-08-25 [CODE] Bottom blank-bar mechanism: height:100vh (css/shared.css:12 / css/unified.css:6) when the effective layout viewport is SHORTER than the physical screen (letterboxed standalone: innerHeight/100vh = screen.height − status-bar Δ, visualViewport.offsetTop=0) → strip y∈[H−Δ,H] is outside the layout viewport → unpaintable blank bar at the physical bottom. Same bug class as WebKit 313800 (iOS 26.3.1) / 317153 (iOS 27 betas); geometry can be baked at install time (reinstall the Home Screen app after meta/viewport changes). If instead env(safe-area-inset-top)=0 while a status bar is visible, the symptom is top content tucked under the translucent bar — NOT a bottom bar.
